for the W3C Credentials Community Group,
written by [Benjamin Goering](https://bengo.is/), an editor of the spec.

## Recent Work in v0.4.0

The goal of v0.4.0 has been to ship low cost, high impact readability improvements,
make the examples conform to the behaviors the spec already describes,
and to do it quickly and safely by making only non-normative changes.
Here's what that looks like in practice.

### Highlights

* **No more inline `[TODO: ...]` text.**
  Notes about future work no longer interrupt the reader.
  They were either hidden as HTML comments or moved to the Backlog appendix,
  where they can be prioritized.
* **Normative text lives in the "Capabilities" and "Invocations" sections**, not the "Introduction".
  The Introduction is now introductory,
  and readers looking for requirements know where to find them.
* **All examples are consistently formatted.**
* **All examples use `DataIntegrityProof`**, not older proof types like `RsaSignature2016` and
  `Ed25519Signature2020`, so the examples reflect the proofs people actually use today.
* **Every version of the spec now has its own URL.**
  GitHub Pages deploys each version under its own path, so you can link to the exact version you mean,
  e.g.
  * <https://w3c-ccg.github.io/zcap-spec/v0.3.0/>
  * <https://w3c-ccg.github.io/zcap-spec/v0.4.0-rc.5/>

### Something We Won't Do: Add `DataIntegrityProof` to the zcap Context

Issue [#95](https://github.com/w3c-ccg/zcap-spec/issues/95) proposed that the zcap JSON-LD context
should include the term `DataIntegrityProof`.

We're not going to do this any time soon.
While working on it, I learned more about how `zcap-v1.jsonld` is used,
and the lesson is that we should never add to it.
Implementations depend on that context being exactly what it is today.

Ideas for a future context are collected under the
[`zcap-context-v2` issue label](https://github.com/w3c-ccg/zcap-spec/issues?q=state%3Aopen%20label%3A%22zcap-context-v2%22).

## Fun: zcap-spec-examples

[zcap-spec-examples](https://gobengo.github.io/zcap-spec-examples/?url=https://w3c-ccg.github.io/zcap-spec/)
extracts every example from the zcap-spec, so each one can be checked and reused on its own.
It's been useful for making sure every example in the spec has the properties the spec requires.

Open the link above to see the examples of the latest spec extracted live in your browser.
Change the `?url=` to point at any version of the spec.

### HTML

The library is hosted as ES modules, so any page can import it with no install and no build step:

<pre class="html"><code>&lt;script type="module"&gt;
  import { extractExamples } from "https://gobengo.github.io/zcap-spec-examples/lib/examples.js";

  const response = await fetch("https://w3c-ccg.github.io/zcap-spec/v0.4.0-rc.5/");
  for await (const example of extractExamples(response)) {
    console.log(example.name, example);
  }
&lt;/script&gt;</code></pre>

### CLI

Pipe any version of the spec into it to get the examples as newline-delimited JSON:

```shell
curl -sS https://w3c-ccg.github.io/zcap-spec/v0.4.0-rc.5/ | npx zcap-spec-examples
```

## Fun: zcap-zod

[zcap-zod](https://gobengo.github.io/zcap-zod/) is a set of [Zod](https://zod.dev) schemas
for the zcap data model: root zcaps, delegated zcaps, and capability invocations.
Every constraint in the schemas is annotated with the normative statement from the spec that it encodes.

The [demo page](https://gobengo.github.io/zcap-zod/) lets you paste, link to, or drop a zcap JSON file to check it.

It checks the data model only. It doesn't verify signatures; that's a Data Integrity implementation's job.

### HTML

Paste this into any `.html` file. It needs no install and no build:

<pre class="html"><code>&lt;script type="module"&gt;
  import { RootZcap } from "https://gobengo.github.io/zcap-zod/zcap-zod/index.js"

  const root = RootZcap.parse({
    "@context": "https://w3id.org/zcap/v1",
    id: "urn:zcap:root:https%3A%2F%2Fexample.com%2Ffoo",
    controller: "did:key:z6MkfWKcvBiKCfNgz5UUGseNt37t4dguEvFgJ9XvX2UV6zB9",
    invocationTarget: "https://example.com/foo",
  })
  console.log(root)
&lt;/script&gt;</code></pre>
